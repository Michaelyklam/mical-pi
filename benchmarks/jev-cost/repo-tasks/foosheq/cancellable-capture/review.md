# Cancellable staged device capture

## Context

The committed reader already uses an allowlisted read-only HID protocol, verifies two complete passes, tracks disconnects, bounds transport waits and closes handles before publishing a snapshot. The new feature adds caller cancellation and a model-level staging controller. Existing safety behavior is retained rather than replaced by a simplified fake reader.

Split: `calibration`. Estimated difficulty: hard. Kind: `feature`.
These are author estimates, not measured model outcomes. This task is independent of the other three tasks; its baseline contains none of their solutions.

## Why this needs repository work

Cancellation races the chooser, open, send, response and close. The chooser must still run synchronously under user activation. A late open needs cleanup even after the public promise rejects. Separately, the controller must reject stale progress/results after cancel and restart, stage a detached snapshot, and import through editor/history helpers without damaging an active transaction.

The baseline contains 10 unmodified committed source/test/fixture files (4,416 lines, 140,168 bytes), plus an authored minimal ESM package and test configuration. It retains the complete selected modules and their existing tests, not extracted toy functions. The task is limited to model modules; UI wiring and visual behavior are explicitly outside scope.

Reference replacement paths:

- `src/lib/device.ts`
- `src/lib/deviceCapture.ts`

- Explicit apply, active-transaction deferral, one-step undo, membership restoration, fixed-point precision and storage isolation.
- End-to-end controller use of the actual reader against a trusted mock transport.
