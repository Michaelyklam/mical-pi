# Portable raw capture transcripts

## Context

The committed reader verifies live two-pass captures and includes both synthetic tests and a checked-in read-only 63-byte capture fixture. The task adds a portable transcript and offline replay. It requires extracting shared pure protocol verification while retaining existing transport timing and cleanup semantics. It is a new support-report feature; no historical incident is asserted.

Split: `evaluation`. Estimated difficulty: hard. Kind: `feature`.
These are author estimates, not measured model outcomes. This task is independent of the other three tasks; its baseline contains none of their solutions.

## Why this needs repository work

A transcript must retain accepted raw bytes without confusing backing-buffer padding, duplicate reports or unrelated events with replies. Replay needs the same early protocol checks and final editor-range validation as live capture, including exact fixed-point comparison and unknown slot state. A JSON shape validator alone is insufficient. The snapshot-only and transcript APIs must share one transport guard and return only after successful verification and close.

The baseline contains 6 unmodified committed source/test/fixture files (3,067 lines, 97,113 bytes), plus an authored minimal ESM package and test configuration. It retains the complete selected modules and their existing tests, not extracted toy functions. The task is limited to model modules; UI wiring and visual behavior are explicitly outside scope.

Reference replacement paths:

- `src/lib/device.ts`
- `src/lib/deviceProtocol.ts`
- `src/lib/deviceTranscript.ts`

## Hidden coverage

- Exact synthetic fixed-point replay, the real committed capture fixture, ignored-but-preserved tails and detached schema projection.
- Forbidden browser/storage access on replay and original timestamp preservation independent of replay time.
- Canonical timestamp and UTF-8 size validation; ordered read allowlist, request lengths, report IDs, response correlation and dense byte arrays.
- Missing/extra/duplicate/out-of-order records, truncated/oversized replies, unsupported firmware/type, pass mismatches and inclusive editor/decoder bounds.
- Actual live reader with offset DataViews, synchronous mutation of input buffers, wrong/duplicate events, send/close waits, shared guard and failure-without-partial-output.

Hidden expectations are handwritten from the feature contract. They use explicit values and independent synthetic messages, not reference implementation imports, golden output generated by the reference, source-text pattern matching or implementation hashes. Required export checks prevent a missing function from passing rejection-only assertions. Existing tests remain unchanged and visible.
