# Identify provider accounts by provider, upstream identity, and user label

Provider ID alone can silently combine different real accounts after re-authentication, while credential fingerprints can split one account when keys rotate. Track OAuth-backed accounts by Pi provider ID plus the stable identity reported by the upstream company. For API-key and gateway providers that expose no stable account identity, ask the user for an account label at Pi startup after the credential is configured and use that label within the provider as the stable identity. Labels are also the friendly footer display name and may override an upstream-derived label; raw credentials and UUIDs are never displayed. Different provider IDs remain separate even when they resolve to the same upstream organization. Future usage records persist this identity, while legacy provider-only history is mapped to the account currently configured for that provider during migration.
