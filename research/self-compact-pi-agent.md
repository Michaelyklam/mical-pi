## What it is

A single Pi extension (`apps/self-compact/extensions/self-compact/self-compact.ts`) that gives an out-loop agent a *visible* context gauge and a *self-authored* handoff note, then drives compaction from that instead of waiting for Pi's near-the-wall trigger. Entry point is `self-compact.ts`; five pure helper modules (`defaults.ts`, `thresholds.ts`, `summary.ts`, `state.ts`, `prompts.ts`, `context-bar.ts`).

## Triggers and thresholds

- Three thresholds resolved against `ctx.model.contextWindow`, not against Pi's `contextWindow - reserveTokens`:
  - `notice` (`--compact-soft-at`, default **10%**), `warning` (`--compact-at`, default **20%**), hard cutoff = `warning + buffer` (`--compact-buffer`, default 10% → **30%**), capped at **90%** of the window (`HARD_CAP_FRACTION = 0.9`, `defaults.ts:27`; resolution `thresholds.ts:121-176`).
  - Values accept tokens (`270000`), `k`/`m`, or `%`; explicit invalid values are rejected and make the extension "inert" (all tools blocked), defaults that don't fit a small window are clamped (`thresholds.ts:74-176`).
  - `levelFor` uses `>=`, forced wins ties, so `buffer=0` enforces at the warning line (`thresholds.ts:193-200`).
- Level detection happens in `trackLevel()` (`self-compact.ts:319-338`), driven by `ctx.getContextUsage()` (`snapshotUsage`, `self-compact.ts:253-266`) and fired from `before_agent_start`, `model_select`, `context`, `message_end`, `tool_call`, `turn_end`, `agent_end`.
- Phase behaviour:
  - **notice**: one transient message per active call; nothing blocked.
  - **warning**: transient message telling the agent to finish the atomic step and call `self_compact`; nothing blocked.
  - **forced** (≥ hard cutoff): `setLocked(true)`; every tool except `self_compact` and `view_context` returns `{block: true}` from the `tool_call` hook (`self-compact.ts:324-325`, `787-825`). Tool *list* is not narrowed, so the model sees a block reason naming `self_compact` rather than "tool not found".
- The extension **cancels Pi's native auto-compaction**: `session_before_compact` returns `{cancel: true}` for any `reason !== "manual"` (`self-compact.ts:846-854`), i.e. both `threshold` and `overflow` triggers. The test asserts this (`tests/parity/extension.test.mjs:85-98`). So native compaction can't bypass the note. Manual `/compact` still runs, but through the extension's replacement summary prompt.
- Additional agent-facing affordance: a `view_context` tool returns the same numbers as JSON (`self-compact.ts:484-506`), and a static system-prompt line tells the agent to call it and to continue from the returned note (`self-compact.ts:79`).
- Final-turn safety: `agent_end` sends one hidden follow-up prompt if the run ended at warning/forced with no handoff (`self-compact.ts:827-834`).

## Summary generation

- The agent must call `self_compact({ note_to_self })` (1–24,000 chars, whitespace-trimmed checks but bytes preserved). The tool saves the note, sets the lock, and returns `terminate: true` to end the run (`self-compact.ts:508-575`). It **refuses** if Pi would find nothing to compact, using `hasCompactionMaterial()` (`summary.ts:22-49`) with the *actual* configured `keepRecentTokens` read from `SettingsManager` (`summary.ts:51-53`; `self-compact.ts:314-316`, `531-540`).
- After `agent_settled` (idle), the extension calls `ctx.compact()` itself (`startCompaction`, `self-compact.ts:373-390`, `836-844`). `ctx.compact()` emits `reason: "manual"` (Pi dist `core/agent-session.js:1468-1471`), so it passes the cancel guard. Built-in `/compact` also lands here.
- Summary is generated by reusing Pi's own `compact()` engine (`summary.ts:93-133`) — same split-turn handling, previous-summary merging, file tracking, cut points, and retry settings. Differences layered on top:
  - A custom **compaction system prompt** — `--compact-prompt` > `<cwd>/.pi/self-compact/USER_PROMPT_COMPACTION_MESSAGE.md` > built-in (`prompts.ts:104-110`, `self-compact.ts:855-866`). The built-in prompt forbids continuing the task and fixes the Pi-style structured format.
  - **Replacement user instructions** appended to the serialized history, with input truncated to a computed char budget (`summary.ts:55-91`). It matches complete known inputs so tag-like text in history can't truncate the conversation.
  - Calls `ctx.modelRegistry.complete` with `cacheRetention: "none"`, a fresh `sessionId`, `maxTokens` capped at 8192, and `reasoningEffort: "low"` for `openai-completions` reasoning models (`summary.ts:108-127`).
  - Up to `SUMMARY_ATTEMPTS = 2` attempts; on success it records `handoffId`, cycle, prompt sources, and truncation flag in `CompactionEntry.details` (`self-compact.ts:867-889`).

## Retention

Unchanged from stock Pi: the new summary still keeps the newest `keepRecentTokens` (default 20,000) untouched via Pi's `findCutPoint`. The extension *adds* the note on top; the note is never folded into or replaced by the summary (README "Where it can still fail"). The `hasCompactionMaterial` guard means thresholds below the retained window silently do nothing.

## Resumption

- The saved note is returned **verbatim** as a `custom_message` (`HANDOFF_TYPE`) via `pi.sendMessage(..., {triggerTurn: true})` once compaction succeeds and the session is idle (`deliverHandoff`, `self-compact.ts:355-369`); content is exactly `h.note`.
- Durable state: a `PersistedState` snapshot entry (`version`, `cycle`, `locked`, `handoff{id,note,status,attempts,savedAt,error}`) is appended on every transition (`state.ts:8-37`, `self-compact.ts:246-248`). Handoff status is a 5-state machine: `pending → compacting → ready → done`, plus `failed`.
- Recovery reducer rebuilds state from the session branch on `session_start` and `session_tree` (`recoverState`, `state.ts:65-95`; `recover`, `self-compact.ts:666-733`). It detects: compaction landed (id in `CompactionEntry.details`), handoff journaled but unanswered (resumes without a user prompt), and journaled-and-answered (marks done, never restarts).
- Failure handling: on compaction failure the note and lock survive; auto-retry up to `MAX_AUTO_RETRIES = 3` with backoff `2s × attempt` (`self-compact.ts:392-399`, `912-931`). `/self-compact-now` reuses the saved note; `/compact` and session reload also recover.
- Each cycle bumps `R.state.cycle`; epoch tracking re-arms guidance and invalidates stale timers across compaction/session/tree events.

## Caveats (from README + implementation)

- Token counts are Pi's **estimate**; a single huge tool result can jump past a threshold before the lock engages.
- The lock blocks *new* tool calls; tools already running when the note is saved finish on their own.
- A model can ignore the warning; the forced phase (blocked tools) exists for that case.
- Compaction quality is model quality; the summary prompt is user-editable.
- Very small sessions have nothing to compact; `self_compact` refuses and the agent keeps working. Thresholds should stay above `keepRecentTokens`.
- Because native auto-compaction is cancelled, the extension's own thresholds are the only safety net while loaded; if thresholds are set too high or invalid, native overflow/threshold checks won't rescue the run (invalid settings block every tool instead).
- Extension targets Pi **v0.85.1**; installed baseline here is **0.84.4**, so API/hook details may drift.
- The project ships its own `ai_docs/` doc bundle (Pi v0.85.1) rather than depending on live docs.

## Direct comparison: vs. simply lowering Pi's compaction threshold

| Dimension | Earlier compaction via higher `reserveTokens` (stock Pi) | self-compact-pi-agent |
|---|---|---|
| Trigger | `contextTokens > contextWindow - reserveTokens`; raising reserve fires **earlier**, at the chosen distance from the window limit | Three explicit % thresholds (10/20/30% by default) on the model window, cap 90% |
| Agent awareness | None — compaction is invisible until it fires | `view_context` JSON gauge + transient notice/warning guidance on each call |
| Who decides content | Pi generates a generic structured summary; agent gets no warning and no voice | Agent writes `note_to_self` before compaction; note returned verbatim |
| Pre-compaction enforcement | None; compaction fires automatically | `forced` level blocks every tool except `self_compact`/`view_context` until the note is saved |
| Summary prompt | Pi default | Replaceable via `--compact-prompt` or prompt files, plus custom user instructions |
| Retention (`keepRecentTokens`) | Changing it alters how much recent history is kept; **not** a trigger | Same retention semantics, but the note survives independently |
| Native auto-compaction | The trigger | **Cancelled** for `threshold`/`overflow`; only manual `ctx.compact()` proceeds |
| Human involvement | Automatic, no handoff | Designed for out-loop: no human message needed; recovery restores the handoff after reload/tree |
| Failure mode | Falls through to native retry/overflow handling | Note + lock persist, auto-retry ×3, then manual `/self-compact-now`, `/compact`, or reload |

Net: lowering the trigger threshold (by raising `reserveTokens`) only changes **when** Pi's own summary happens; it does not give the agent visibility, a voice in the summary, a tool-enforced checkpoint, or a resumption contract. self-compact is a workflow layer that deliberately disables Pi's auto-compaction and replaces it with an agent-authored, agent-triggered handoff.
